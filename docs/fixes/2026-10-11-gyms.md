# 2026-10-11 · 0단계 PR 3 — 짐(Gym) 구조 · 짐별 운영진 · 아주대 이전

설계: [../design/stage0-gyms.md](../design/stage0-gyms.md) §1 · §4 · §6. 결정(사용자가 "알아서 진행"): 아주대 짐 주소 `ajou-muscleup`,
지금 가입자 전원을 아주대 짐 멤버로, 기존 운동 모임은 아주대 짐의 소모임, 짐 만들기는 승인제.

## 1. 데이터 구조 — `WorkoutCrew` 를 짐으로 키움

- 새 enum: `GymType`(CLUB · CREW · GYM · PT), `GymVisibility`(PUBLIC · UNLISTED · PRIVATE), `GymStatus`(PENDING · ACTIVE · ARCHIVED), `GymFeature`(7개).
- `entity/WorkoutCrew.java` 새 칸: `type` · `slug`(unique) · `visibility` · `status` · `parent_id` · `school_domain` · `region` · `logo_url` · `map_theme` · `member_limit`,
  기능 목록 `gym_features(gym_id, feature)`(@ElementCollection). 기존 행 때문에 DB 에선 null 허용 → `typeOrDefault()` 등으로 읽는다.
- `entity/WorkoutCrewMemberRole.java`: `LEADER, MEMBER` → `OWNER, STAFF, MEMBER`. `WorkoutCrewMember.title`(직함) 추가.

## 2. 권한 — `service/GymPermissionService.java` (새)

- `roleOf(gym, user)`: `gym.owner` 면 OWNER, 아니면 멤버 행의 역할.
- `can/require(user, gym, action)`: 표대로(OWNER 전부 · STAFF 는 MEMBERS · CONTENT · VIEW · MEMBER 는 VIEW). 앱 운영자(ROLE_ADMIN)는 전부.
- `service/CrewServiceImpl.java`: `ensureLeader`(주인 id 비교) 9곳 →
  ```diff
  - ensureLeader(crew, me);
  + gymPermissionService.require(me, crew, GymAction.MANAGE_MEMBERS);   // 가입 승인 · 거절 · 내보내기
  + gymPermissionService.require(me, crew, GymAction.MANAGE_SETTINGS);  // 수정 · 삭제
  + gymPermissionService.require(me, crew, GymAction.MANAGE_CONTENT);   // 챌린지
  ```
  - 운영진은 모임장만 내보낼 수 있음. 동아리 등 CREW 가 아닌 짐은 삭제 불가(보관만).
  - 모임 목록(`list`)은 `type=CREW` · `status=ACTIVE` 만(아주대 짐이 운동 모임 화면에 섞이지 않게).
  - 새 모임: `type=CREW`, `slug="c-"+초대코드 소문자`, 만든 사람 OWNER.
  - 상세 응답 `leader` = 관리 화면을 볼 수 있음(모임장 · 운영진), 새 `myRole`.

## 3. 짐 API — `GymService` · `GymController` · `AdminGymController` (새)

| 요청 | 누가 | 내용 |
|---|---|---|
| `GET /api/gyms?type&q&school` | 누구나 | ACTIVE · PUBLIC 짐, 멤버 많은 순 |
| `GET /api/gyms/mine` | 로그인 | 내 짐(승인 대기 · 보관 포함) |
| `GET /api/gyms/{slug}` | 누구나* | *PRIVATE · 승인 전 · 보관은 멤버 · 운영자만(그 외 404). 초대 코드는 멤버만 |
| `GET /api/gyms/{slug}/members` | 멤버 | 전체 멤버(이메일 없음) |
| `GET /api/gyms/{slug}/members?role=STAFF` | 누구나* | 모임장 · 운영진(운영진 소개 페이지용) |
| `POST /api/gyms` | 로그인 | 만들기. 운영자가 아니면 PENDING. 예약어 주소 400, 중복 409 |
| `PATCH /api/gyms/{slug}` | 모임장 | 이름 · 설명 · 공개 범위 · 가입 방식 · 지역 · 로고 · 기능 |
| `PATCH /api/gyms/{slug}/members/{userId}` | 모임장 | 운영진 임명/해임 · 직함. 모임장 역할 변경 · 넘기기는 아직 없음 |
| `GET /api/admin/gyms?status=` · `POST …/{id}/approve` · `…/archive` | 앱 운영자 | 승인 · 보관 |

`config/SecurityConfig.java`: GET 찾기 · 정보 · 멤버 경로 permitAll(서비스가 로그인 · 멤버 확인), 나머지 `/api/gyms/**` 로그인.

## 4. 데이터 이전 — `db/migration/{postgresql,mysql}/V2__gyms_and_ajou_club.sql`

1. 역할 칸 제약 풀기: Postgres 는 Hibernate 가 만든 `CHECK (role IN ('LEADER','MEMBER'))` 를 찾아 지우고, MySQL 은 `enum(...)` → `VARCHAR(16)`. 그다음 LEADER → OWNER.
2. 기존 모임: `type=CREW` · `status=ACTIVE` · `visibility=PUBLIC` · `slug='crew-{id}'` · `map_theme='GYM'`.
3. 아주대 짐: `득근득근 · 아주대 헬스 동아리`, `CLUB`, `ajou-muscleup`, `ajou.ac.kr`, 가입 방식 승인제, 초대 코드 `AJOU-MUSCLEUP`.
   주인 = 가장 먼저 가입한 앱 운영자(없으면 가장 먼저 가입한 사람). 사용자가 없으면 만들지 않음.
4. 기존 모임 → 아주대 짐 소모임(`parent_id`).
5. 지금 가입자 전원 → 아주대 짐 멤버(주인은 OWNER).
6. 모든 짐에 기능 7개 켬.

모든 단계는 `IS NULL` · `NOT EXISTS` 로 여러 번 돌아도 같은 결과.

## 남은 것

- **운영 배포 = 운영 데이터 변경**(아주대 짐 생성 · 전원 멤버 · 역할 값 변경). 배포 전 Railway 스냅샷 필수.
- 아주대 짐 주인은 "가장 먼저 가입한 운영자" 자동 선택 → 운영진 지정(STAFF)은 사용자가 화면/API 로. 모임장 넘기기 기능은 아직 없음.
- 새로 가입하는 사람은 아주대 짐에 자동으로 들어가지 않는다(짐 고르기 화면은 PR 6).
- 짐 찾기는 짐 수가 적다는 전제로 전체를 읽어 거른다(짐마다 기능 · 부모 · 내 역할을 따로 읽음). 짐이 수백 개가 되면 쿼리로 바꾼다.
- 로그인한 화면(운동 모임 관리 버튼 · 역할 이름)은 로그인이 필요해 화면으로 못 봄.
