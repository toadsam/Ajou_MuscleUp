# 2026-10-13 · 계속 오게 만들기 PR D — 주간 목표 연속 기록

계속 쓰게 만드는 작업(로드맵 아래)의 첫 PR. 헬스는 매일 하면 안 되는 운동이라 "매일 연속"은 끊기기 쉽고, 한 번 끊기면 그만두게 된다.
그래서 **"한 주에 N번"을 몇 주 이어 갔는지**를 센다. 기존 매일 연속 · 연속 보너스는 그대로 둔다.

## 1. 규칙 — `service/WeeklyGoalService.java`
- 한 주 = 월~일(한국 시간 `Clock`). 운동한 날(`didWorkout`) 수 ≥ 그 주 목표면 달성.
- 목표 1~7번, 기본 3번. **이번 주에 아직 운동 안 했으면 바로, 했으면 다음 주부터**(주 중간에 낮춰 연속을 지키는 것 막기).
- 연속: 이번 주는 달성했을 때만 센다(진행 중이면 끊지 않음). 지난주부터 거꾸로 달성한 주를 세고(최대 104주), 쉬는 주는 건너뛴다.
- 쉬는 주: 아직 달성 안 한 이번 주만, 최근 4주 안에 한 번. 쉬는 주에 목표를 채우면 그냥 달성.
- 보너스: 이번 주를 처음 채운 출석에 `8 + 2 × 연속 주(1~6)` = 10~20점, 한 주에 한 번(`rewarded`). 출석 한 번이 보통 6~15점.
  - 출석이 "운동 안 함 → 운동함"으로 바뀔 때만 확인(`AttendanceServiceImpl.doUpsert`). 수정으로 휴식↔운동을 반복해도 한 번뿐.
  - 어제 기록 수정이 지난주(오늘이 월요일)면 연속 계산에만 반영, 보너스 없음.

## 2. 데이터
- `weekly_goal_settings`(사용자당 하나: target), `weekly_goal_weeks`(user, week_start UNIQUE, target, rest, rewarded).
- 주 행은 그 주에 처음 운동했을 때(또는 목표 · 쉬는 주를 바꿀 때)만 만든다. 행이 없는 주(이 기능 전, 운동 안 한 주)는 지금 설정한 목표로 본다 — 기존 사용자도 지난 기록으로 연속이 바로 잡힌다.
- 탈퇴: `AccountDeletionService` 에 두 표 추가, `AccountSafetyTest` 확인 추가.
- 새 표뿐(ddl-auto 로 생김, 이전 SQL 필요 없음). 사용자 수 × 주 수 만큼의 작은 행.

## 3. API — `controller/WeeklyGoalController.java`
- `GET /api/attendance/weekly-goal` → `{weekStart, weekEnd, target, nextTarget, done, days[7], achieved, rest, canRest, streakWeeks, bonusPoints, rewarded}`
- `PUT /api/attendance/weekly-goal` `{target}` · `PUT /api/attendance/weekly-goal/rest` `{rest}`
- 출석 응답(`AttendanceLogResponse`)에 `weeklyGoalBonus` · `weeklyGoalStreak`(이번에 처음 채웠을 때만), `expEarned` 에 보너스 포함.

## 4. 화면
- `components/attendance/WeeklyGoalCard.tsx`: 출석 화면에서 오늘 출석 카드 바로 아래. 바벨 원판 칸 수 = 목표, 끼운 원판 = 이번 주 운동 수(기존 `Barbell`),
  월~일 동그라미, "N번 더 하면 달성 · 보너스 +N" / "이번 주 목표 달성! 보너스 +N 받음" / 쉬는 주 문구, "N주 연속" 칩,
  목표 바꾸기(1~7, 이번 주 적용인지 다음 주부터인지 안내) · 이번 주는 쉬어요 / 쉬는 주 취소. 넓은 화면에서는 바벨 폭 제한(max-w-md).
- 출석 저장 응답에 보너스가 있으면 "주간 목표 달성! N주 연속 · 보너스 +N" 알림, 카드 다시 불러오기.
- 홈 "지금 해야 할 일" 칸: "이번 주 N/7" → "주간 목표 done/target" + "N주 연속".
