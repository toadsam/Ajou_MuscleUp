스크린숏은 PR F(#24)의 옛 화면이었다(8종목 버튼판, 옛 설명 문구). 앱(PWA)에 저장된 예전 화면으로 보인다.

그리고 "운동 기록" 화면에서 빠른 기록 칸이 커서 운동 세션보다 먼저 눈에 띄었다. 이번에 셋을 고쳤다.
1. 직접 추가
2. 최근 한 종목
3. 화면 순서

## 1. 직접 추가: 서버
- **새 표** `custom_exercises`: 사람, 이름(30자), 부위(6개 + 기타 OTHER), 맨몸 여부, 지움 여부. ddl-auto로 만든다.
- **코드** `"C" + id`(예: `C12`)
  - 운동 기록(`lift_entries.exercise`)과 세트(`workout_sets.exercise`)는 원래 문자열이라 칸을 바꾸지 않았다.
  - 그래서 직접 추가한 종목도 개인 최고, 지난번 값, 성장 그래프, 이번 달 목록이 그대로 된다.
  - 3대에는 반영하지 않는다.
- **`ExerciseCatalog`**(새)
  - 기본 31개(`LiftExercise`)와 내 종목을 한 곳에서 찾는다.
  - `resolve(me, code, allowDeleted)`: 남의 종목은 찾지 않는다. 기록을 남길 때는 지운 종목을 빼고, 지난 기록을 볼 때는 넣는다.
  - `describe(codes)`: 이름표.
  - `LiftService`와 `WorkoutSessionService`는 enum 대신 이걸 쓴다. 바뀐 곳은 `record` 인자, 이름표, 지난번 값, 최고 기록판(기본 종목 다음에 내 종목)이다.
- **검사**
  - 이름은 공백을 정리해 1~30자로 받는다.
  - **띄어쓰기 · 대소문자만 다른 같은 이름**은 거절한다(409). 기본 종목 이름과 같아도 거절한다.
  - 부위는 정해진 7개 중 하나여야 한다.
  - 한 사람이 50개까지 만들 수 있다.
- **지우기**: 행은 남기고 `deleted`만 표시한다.
  - 목록, 고르기, 최근, 새 기록에서는 빠진다.
  - **지난 기록의 이름은 그대로 보인다.**
  - 같은 이름으로 다시 추가할 수 있다.
- **API**(`/api/lifts/**`, 원래 로그인 필요)

  | 요청 | 하는 일 |
  |---|---|
  | `GET /api/lifts/custom` | 내 종목 목록 |
  | `POST /api/lifts/custom` | 직접 추가 `{name, category, bodyweight}` |
  | `DELETE /api/lifts/custom/{code}` | 지우기 |
  | `GET /api/lifts/recent` | 최근 한 종목 |

- 탈퇴할 때 삭제하도록 했고, `AccountSafetyTest`에 확인을 넣었다.

## 2. 최근 한 종목
- `GET /api/lifts/recent`: 세션 세트와 빠른 기록에서 종목마다 마지막으로 한 때를 모은다. 새것부터 8개, 지운 내 종목은 뺀다.
- 고르기 화면은 최근이 있으면 **"최근" 칩을 먼저 열어** 바로 누를 수 있게 했다.

## 3. 화면
### `components/lifts/ExercisePicker.tsx`
운동 세션 "종목 추가"와 빠른 기록이 같이 쓴다.
- 칩 순서: 최근 · 전체 · 하체 · 가슴 · 등 · 어깨 · 팔 · 복근. (기타 · 내 종목은 있을 때만 나온다.)
- 이름으로 찾으면 탭과 상관없이 모든 종목에서 찾는다. 없으면 "목록에 없어요. 아래에서 직접 추가해 주세요"를 띄운다.
- 종목 버튼을 키웠다(높이 52px, 15px). 내 종목 · 맨몸 표시를 붙였다.
- **"+ 찾는 종목이 없나요? 직접 추가"**
  - 이름(검색어로 미리 채움), 부위, 맨몸 여부를 받는다. 빠른 기록에서는 맨몸을 숨긴다.
  - "추가"를 누르면 **바로 그 종목을 고른 것**으로 넘어간다. 세션이면 종목 카드가 생긴다.
- "내 종목" 칩에서 지울 수 있다(지난 기록은 남는다고 확인 창으로 안내).

### `lib/lifts.ts`
- 내 종목을 한 번 불러와 여러 화면이 같이 쓴다(`useCustomExercises`, `useSyncExternalStore`).
- `exerciseInfo(code)`는 기본 종목에 없으면 내 종목에서 찾는다.
- 운동 세션과 "운동 기록" 화면이 이걸로 이름과 맨몸 여부를 안다.

### "운동 기록"(`pages/Workout.tsx`)
- **"운동 시작"을 가장 크게** 했다(빨간 테두리, 큰 제목 · 버튼). 그 아래 러닝, 이번 달 운동 순서다.
- **빠른 기록은 접어 둔다**(`<details>` "빠른 기록 · 펼치기").

## 4. 확인
- **새 `CustomExerciseTest`**
  - 추가: 공백 정리, 같은 이름 · 기본 종목 이름 · 빈 이름 · 모르는 부위는 거절. 다른 사람은 같은 이름을 따로 가질 수 있다.
  - 빠른 기록: 첫 개인 최고, 3대 반영 없음, 최고 기록판에서 기본 종목 다음, 그래프.
  - 막는 것: 맨몸 종목을 빠른 기록에 쓰기, 남의 종목 쓰기.
  - 세션: 이름 · 맨몸 · 개인 최고 · 지난번 값이 그대로 된다. 남의 종목은 쓸 수 없다.
  - 최근: 3개, 순서 확인.
  - 지우기: 남이 지우기는 404. 내가 지우면 목록 · 최근 · 새 기록에서 빠지고, 지난 기록 이름은 남는다. 같은 이름으로 다시 추가할 수 있다.
- 기존 `LiftTest` · `WorkoutSessionTest` · `AccountSafetyTest`가 통과했다. 백엔드 전체 테스트 결과는 PR 본문에 적었다.
- `verify.sh` 통과(린트 늘어난 파일 없음, 빌드).
- **로컬 화면**(시험용 계정, 375px)
  - "운동 기록": 운동 시작이 맨 위에 크게, 빠른 기록은 접혀 있다.
  - 세션 "종목 추가": "최근" 칩이 먼저 열리고 스쿼트가 보인다.
  - "케이블 풀오버"를 찾으면 "목록에 없어요"가 뜨고, 직접 추가(이름이 미리 채워짐) → 등 → 추가 → 세션에 "케이블 풀오버" 카드가 생긴다.
  - 서버에 부위가 BACK으로 저장된 것을 확인했다. 가로 넘침은 없다. 시험 데이터는 지웠다.
