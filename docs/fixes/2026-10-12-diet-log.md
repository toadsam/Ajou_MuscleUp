# 2026-10-12 · 식단 기록 PR A — 직접 입력 · 하루 합계 · 목표 비교

다음 단계(PR B)는 음식 사진 → AI 인식 → **확인 화면** → 이 기록에 저장. 그래서 A 에서 "고칠 수 있는 기록"을 먼저 만들었다.
AI 가 양을 ±20~30% 틀릴 수 있어, 사진 결과도 결국 여기서 고치고 지우게 된다.

## 1. 데이터
- `MealEntry`(`meal_entries`, 인덱스 `user_id, eaten_on`): 한 줄 = 음식 하나. 먹은 날(KST) · 끼니(`MealType` 아침/점심/저녁/간식) · 이름(60자) · 양(자유 글 30자) · kcal · 단백질/탄수화물/지방 g(모두 선택) · `source`.
- `DietGoal`(`diet_goals`, 사용자당 하나): kcal · 단백질 · 탄수화물 · 지방 · `source`.
- `DietSource` = `MANUAL | PHOTO | INBODY`. **PHOTO 를 미리 넣었다** — 새 테이블이라 지금 넣으면 PR B 에서 enum 제약 이전 SQL(CLAUDE.md "enum 칸에 새 값")이 필요 없다.
- 새 테이블뿐이라 이전 SQL 없음(Hibernate `ddl-auto=update` 가 만든다).

## 2. API — `DietController` / `DietService` (`/api/diet/**`, USER · ADMIN)
| | |
|---|---|
| `GET /day?date=` | 하루 기록(끼니 순, 끼니 안은 입력 순) · 합계 · 목표 · 서버 기준 오늘 |
| `GET /summary?from=&to=` | 날짜별 합계, 기본 최근 7일, 최대 31일(넘으면 400) |
| `GET /recent-foods` | 최근 200개 중 이름이 다른 20개(다시 넣기) |
| `POST /entries` · `PUT /entries/{id}` · `DELETE /entries/{id}` | 추가 · 고치기 · 지우기. 남의 기록 id 는 404 |
| `GET/PUT/DELETE /goal` | 목표. 저장된 목표가 없으면 체중(`user_body_stats`) × 1.6g 단백질 **제안**(`saved:false`), 둘 다 없으면 204 |

검사: 이름 필수 · 끼니 필수 · 앞으로의 날짜 / 2020년 이전 400 · kcal 0~5000 · g 0~500(소수 첫째 자리로) · 하루 60개까지.
`DietService.add(me, req, source)` 는 PR B 가 `PHOTO` 로 부를 자리.
