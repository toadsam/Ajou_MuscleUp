## 왜
앱을 열지 않으면 연속 기록 · 주간 목표 · 응원을 알 길이 없었다.
사용자와 정한 규칙:
- **하루 최대 2개**
- **종류별로 끌 수 있음**
- **조용한 시간**에는 보내지 않음
- VAPID 키는 사용자가 Railway에 넣음

## ⚠ 운영에서 켜려면(사용자가 할 일)
1. 키를 만든다. Node가 있는 PC에서 한 번 실행한다. 출력되는 두 값은 비밀이니 어디에도 붙여 넣지 않는다.
   ```bash
   npx web-push generate-vapid-keys
   ```
2. Railway 백엔드 서비스 → Variables에 넣는다.
   - `PUSH_VAPID_PUBLIC_KEY` = Public Key
   - `PUSH_VAPID_PRIVATE_KEY` = Private Key
   - (선택) `PUSH_VAPID_SUBJECT` = `mailto:관리자메일` 또는 `https://musclehub.co.kr`. 없으면 `https://musclehub.co.kr`로 쓴다.
3. 다시 배포되면 `GET /api/push/config`가 `{"enabled":true,...}`를 돌려준다.
   - 키가 없거나 형식이 틀리면 알림은 꺼진 채로 동작한다. 서버 로그에 `[push] ...`가 남고, 화면에는 "알림을 준비하고 있어요"가 나온다.
4. **키를 한 번 넣으면 바꾸지 않는다.** 바꾸면 그동안의 구독이 모두 무효가 되어 다시 켜야 한다.

## 1. 서버
### 암호: `push/WebPushCrypto` (JDK만 사용, 새 라이브러리 없음)
- 본문 암호화: RFC 8291 + RFC 8188 `aes128gcm`.
  - ECDH P-256, HKDF-SHA256, AES-128-GCM을 쓴다.
  - 레코드는 하나이고 크기는 4096이다.
- 서버 인증: RFC 8292 VAPID. ES256 JWT를 쓰고, JDK DER 서명을 R‖S 64바이트로 바꾼다.
- **RFC 8291 5절 예시 값으로 결과가 바이트 단위까지 같은지 테스트한다**(`rfc8291Example`).

### `push/VapidKeys`
- 환경변수에서 키를 읽는다.
- 운영(prod)에 키가 없으면 알림을 끈다.
- 개발에서는 서버를 켤 때마다 임시 키를 만든다(다시 켜면 다시 구독해야 함).

### `push/PushSender`
- 암호화한 뒤 `TTL 12시간`, `Urgency normal`로 POST한다.
- 결과 처리:
  - 201 등 성공은 OK.
  - **404 · 410은 구독이 사라진 것이라 지운다.**
  - 그 밖의 응답은 다음 기회로 넘긴다.

### `push/PushService` — 규칙
- **하루 2개**까지 보낸다(`push_logs`로 센다). 시험 알림은 따로 하루 3번까지.
- **종류별 끄기**:
  - `REMINDER`: 저녁 출석
  - `WEEKLY`: 주말 주간 목표
  - `SOCIAL`: 응원 · 댓글
  - 처음 구독하면 셋 다 켜진다.
- **조용한 시간**: 밤 10시 ~ 아침 8시(한국 시간)에는 보내지 않는다. 그 사이 생긴 응원 알림은 쌓지 않고 버린다.
- **구독 주소 제한**: 알려진 푸시 서비스(FCM · Mozilla · Apple · Windows)의 https만 받는다. 서버가 아무 주소로나 요청을 보내지 않게(SSRF) 막은 것이다.
- **기기 제한**: 한 사람에 5대까지. 넘으면 가장 오래된 기기를 뺀다. 같은 기기가 다른 계정으로 켜면 그 계정으로 옮긴다.
- **알림 내용**: `{title, body, url, tag}`. `url`은 사이트 안 주소(`/...`)만 넣고, 아니면 `/`로 바꾼다.
- **보내는 시점**: 응원 · 댓글은 `PushEvent`로 남긴다. 받는 쪽은 `@Async @TransactionalEventListener`라서 **커밋 뒤에 따로** 보내고, 요청을 붙잡지 않는다.

### 언제 보내나
- **매일 19:00** `PushScheduler.dailyReminder`: 오늘 아직 출석하지 않은 사람에게 보낸다.
  - 연속 기록이 2일 이상이면: "연속 N일째, 오늘도 이어 가요"
  - 주간 목표가 남았으면: "이번 주 목표까지 N번"
  - 그 밖에는: "오늘 운동했나요?"
- **토 · 일 18:00** `weeklyNudge`: 주간 목표가 남았고, 남은 날 안에 아직 채울 수 있고, 오늘 출석하지 않았으면 "이번 주 목표까지 N번 남았어요 / 채우면 보상 상자가 확정이에요!"
- **응원**(`AttendanceServiceImpl.addCheerBySlug`): 새 응원이 오면 "응원을 받았어요"를 보낸다. 본인이 누른 건 빼고, 로그인한 사람이면 닉네임을 넣는다.
- **댓글**(`BragInteractionServiceImpl.addComment`): 글쓴이에게 "새 댓글 / 닉네임: 앞 40자"를 보낸다. 내 글이거나 서로 차단한 사이면 보내지 않는다.
- **매일 04:20**: 30일 지난 보낸 기록을 지운다. 보낸 기록에는 내용을 남기지 않고 종류 · 시각 · 기기 수만 남긴다.

### API (`/api/push`)
| 요청 | 하는 일 |
|---|---|
| `GET /config` | 로그인 없이. 켜져 있는지와 공개 키 |
| `GET /me` | 구독 기기 수, 종류별 설정, 오늘 보낸 수 |
| `POST /subscribe` | 구독 |
| `POST /unsubscribe` | 구독 해제 |
| `PUT /preferences` | 종류별 켜고 끄기 |
| `POST /test` | 시험 알림 |

- 새 표 `push_subscriptions`(endpoint · SHA-256 · p256dh · auth), `push_preferences`, `push_logs`는 ddl-auto로 만들어진다.
- 탈퇴 삭제와 `AccountSafetyTest` 확인을 추가했고, 처리방침 초안에 줄을 추가했다.

## 2. 화면
- **`public/push-sw.js`**: vite-plugin-pwa가 만드는 `sw.js`가 `importScripts`로 불러온다(`vite.config.ts` `workbox.importScripts`).

  - 빌드본 `dist/sw.js`에 `importScripts("push-sw.js")`가 들어간 것을 확인했다.

  - 지원 여부 판단: 지원 안 함 · iPhone은 홈 화면 앱 필요 · 차단됨.
  - 켜기: 권한 요청 → 공개 키 → `pushManager.subscribe` → 서버. 버튼을 누른 순간에 불러야 한다.
  - 끄기.
- **마이페이지 "알림" 카드**(`components/push/PushSettings.tsx`, 차단한 사람 칸 위)
  - "알림 켜기 / 이 기기 알림 끄기"
  - 종류 3개를 체크로 켜고 끈다(언제 오는지 설명 포함).

## 3. 확인
- **새 `PushTest` 5개**(시각을 토요일 18:30으로 고정, 보내는 쪽은 기록만 하는 가짜)
  - **구독 · 한도 · 끄기**
    - 바깥 주소, http, 틀린 키는 거절한다. 같은 기기를 다시 구독해도 1대로 센다. 2대 등록.
    - 시험 알림이 두 기기에 가고, 4번째는 429.
    - 응원 2번은 가고 3번째는 0. 바깥 url은 `/`로 바뀐다.
    - 응원을 끄면 0. 410이면 구독이 지워진다. 해제하면 내 기기만 지워진다. 로그인이 필요하다.
  - **정해진 시각 알림**: 출석하지 않은 사람에게만 "이번 주 목표까지 3번"이 간다.
    - 토요일에 주 3번 목표를 0번 했으면 못 채우니 주간 알림을 보내지 않는다.
    - 목표를 2번으로 낮추면 "2번 남았어요"를 보낸다.
  - **조용한 시간 경계**: 22:00 · 03:00 · 07:59는 조용, 08:00 · 21:59는 보낸다.
  - **암호**
    - 암호화한 걸 받는 쪽처럼 풀면 원문이 나온다. 길이는 헤더 86 + 본문 + 구분자 1 + 태그 16.
    - JWT 서명을 JDK로 검증했다.
    - **RFC 8291 예시와 바이트까지 같다.**
- 백엔드 전체 테스트를 MySQL과 Postgres 17에서 돌렸다(결과는 PR 본문). `verify.sh` 통과.
- **로컬 화면**(375px)
  - 미리보기 브라우저는 알림 권한이 차단되어 있어 "알림이 차단되어 있어요" 안내가 맞게 나온다.
  - 시험용 구독을 서버에 직접 넣었을 때 종류 3개 · "기기 1대 · 오늘 0/2"가 나온다.
  - "응원 · 댓글"을 끄면 서버에 저장된다.
  - 시험용 구독은 지웠다.

## 4. 확인 못 한 것
- **실제 알림 도착**(FCM · 아이폰)은 확인하지 못했다. 미리보기 브라우저는 알림이 차단되어 있고, 운영 키도 아직 없다.
  - 키를 넣고 배포한 뒤, 휴대폰 Chrome(또는 아이폰 홈 화면 앱) → 마이페이지 → 알림 켜기 → "시험 알림 보내기"로 확인해야 한다.
- 서버가 여러 대로 늘면 19:00 알림이 겹쳐 나갈 수 있다. 지금은 한 대다.
- 휴식 타이머가 끝났을 때 화면이 꺼져 있으면 알리는 건 아직 하지 않았다. 서버가 그 시각을 알아야 해서 따로 만들어야 한다.
